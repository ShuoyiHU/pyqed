# LETTA U(1)/SU(2) validation benchmark

Environment: macOS 15.7.4 arm64, Python 3.12.12, NumPy 2.4.2, one BLAS
thread. Each entry is the median of three interleaved runs. Wall time is from
an untraced solve; peak allocation is measured by `tracemalloc` in a separate
untimed replay. All methods use scalar gauge balancing and the same convergence
tolerance.

## One-site Heisenberg chain, N=8

Command:

```bash
PYTHONPATH=. \
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 \
python -m pyqed._letta_two_site_opt.benchmarks.heisenberg_symmetry \
  --nsites 8 --solver one-site --multiplets-per-sector 3 \
  --max-sweeps 8 --tolerance 1e-9 --repeats 3 --seed 7 \
  --json-output /private/tmp/letta_su2_n8_one.json
```

| symmetry | energy | median time (s) | parameters | peak (MiB) | max local dim |
|---|---:|---:|---:|---:|---:|
| none | -3.37493259868789 | 10.1264 | 17,658 | 98.65 | 2,916 |
| U(1) | -3.37493259868789 | 1.8863 | 4,665 | 67.64 | 972 |
| SU(2) | -3.37493259868789 | 1.0608 | 168 | 2.73 | 36 |

All runs converged. Relative to no symmetry, exact reduced SU(2) used 0.95%
of the parameters, 2.77% of the traced peak memory, and 10.5% of the time.

## Two-site Heisenberg chain, N=6

Command:

```bash
PYTHONPATH=. \
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
VECLIB_MAXIMUM_THREADS=1 NUMEXPR_NUM_THREADS=1 \
python -m pyqed._letta_two_site_opt.benchmarks.heisenberg_symmetry \
  --nsites 6 --solver two-site --multiplets-per-sector 3 \
  --max-sweeps 12 --tolerance 1e-10 --repeats 3 --seed 7 \
  --json-output /private/tmp/letta_su2_n6_two.json
```

| symmetry | energy | median time (s) | parameters | peak (MiB) | max local dim |
|---|---:|---:|---:|---:|---:|
| none | -2.49357713388793 | 1.2465 | 5,292 | 30.61 | 2,592 |
| U(1) | -2.49357713388793 | 0.3021 | 1,566 | 27.13 | 720 |
| SU(2) | -2.49357713388793 | 0.1515 | 16 | 0.53 | 15 |

All runs converged. The three-multiplet initial capacity matters: with only
one copy per reachable SU(2) sector, this N=6 two-site state is too small to
reach the common ground energy, and increasing `bond_dim` alone cannot add a
multiplet absent from the initial allocation. The benchmark reports
`agreement.efficiency_comparison_valid = false` for such under-capacity runs.

Absolute times are machine-dependent. Energy agreement, stored parameter
counts, local dimensions, and allocation peaks are the portable checks.
